# Intensive parity and performance audit — 2026-11-21

Three independent, read-only agent audits ran for approximately 30 minutes each (08:03–08:33 UTC). They compared the productive Windows path (`src/main.ml` → `qvm_menu_app.ml` → `qvm_preview_app.ml` → `local_qvm_match.ml`) with the checked-in Quake III source. Findings below concern that path; existence of a separate port module or passing unit test does not establish that the executable uses it. No implementation changes were made in this audit.

## Additional confirmed parity defects and performance risks

- The same bot binder omits `gapDistanceFn` and `againstLadderFn`; their fallbacks return zero/false (`ai_move_runtime.ml:166,514-515`). The original checks gaps and ladders in `be_ai_move.c` and `be_aas_move.c`. Moving platforms are also absent from the productive bot movement choice.
- `ai_move_runtime.ml:191-200` recomputes routes for candidate reaches; `aas_routing_cache.ml:205-225` keys entries by exact moving-origin floats and recomputes on misses. The original caches by target, cluster and flags (`be_aas_route.c:1661-1686`). Extra work is certain; FPS impact is unmeasured. The fresh package also lacks `qvms/maps` for `.rcd` cache saves (`local_qvm_match.ml:414`).
- `local_qvm_match.ml:204` appends every print with list concatenation and never bounds the transcript. Memory and total copy work grow throughout a long match. This is a structural problem, not a proven explanation of the user's reported freezes.
- Fullscreen Setup/Controls still invokes Cgame and prepares BSP/portal world views (`qvm_preview_app.ml:432-456`) before skipping world draw. Original `code/client/cl_scrn.c:448-453` skips Cgame rendering as soon as UI is fullscreen.
- The disconnected menu discards native `WM_CHAR` and synthesizes US characters from keydown (`qvm_menu_app.ml:106-113`, `original_ui_session.ml:69-76,116-139`). German Y/Z, shifted symbols, Caps Lock and key repeat can differ from Windows/Quake input.
- Runtime UI file lists return no mods or local demos (`local_qvm_match.ml:1593-1609`) despite original `ui_mods.c` and `ui_demo2.c` enumeration.
- The productive BSP patch path tessellates at a fixed error of 4 (`world_surface_selection.ml:138-153`); the camera-dependent LOD module is not connected. `qvm_viewport.ml:33-37` derives vertical FOV instead of honoring refdef `fovY`. A later static opaque shader stage can be skipped (`playable_world_batch.ml:158-170`). `r_picmip` and `r_textureMode` do not govern native texture creation/filtering (`playable_gl_renderer.h:265-267`).
- Portal rendering may rebuild complete world batches and search visible triangles linearly for portal materials (`retained_world_batch.ml:166-177`, `portal_render_pass.ml:13-43`). This requires measurement on a portal-heavy Retail scene before ranking it as an FPS cause.
- Audio queues three 4096-frame buffers at 22050 Hz, a theoretical queued duration up to about 0.56 seconds; perceived latency was not measured.
